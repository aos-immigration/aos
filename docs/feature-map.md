## API

### `GET /health`

Status: wired.

Liveness response {"ok": true}.

Reach it from GET http://localhost:8000/health while the API is running.

Verify: bun run check runs apps/api/tests/test_api.py::test_health_ok. The test uses FastAPI TestClient and does not bind a port.

### `GET /fields/{slug}`

Status: wired.

Lists AcroForm leaf fields for Forms/{slug}.pdf. Any filename in Forms/ is a slug. Only i-130 is used by the UI.

Reach it from GET /fields/i-130 on the API.

Verify: bun run check runs test_unknown_form_is_not_found. A real listing is GET /fields/i-130 against a running server, or the catalog apps/api/data/i-130.fields.csv.

### `GET /debug/field/{slug}`

Status: wired.

Dumps one field's /AP, /V, /AS, and parent. The name query must be URL-encoded, with brackets as %5B and %5D.

Reach it from GET /debug/field/i-130?name=... on the API.

Verify: bun run check runs test_debug_field_requires_a_name. Inspect a live field only when the server is up.

### `POST /fill/{slug}`

Status: wired.

Fills Forms/{slug}.pdf from {fields, checkboxes} and streams the PDF back. The caller must send X-Fill-Secret. Checkbox on-values are sniffed from /AP. /V and /AS are both set, and /NeedAppearances is set on the AcroForm.

Reach it from the signed-in Verify & Preview button, which calls the Convex fill action, or POST /fill/i-130 with the shared secret.

Verify: bun run check runs apps/api/tests/test_fill_auth.py and uv run python scripts/eval_fill.py fixtures/ from apps/api. eval_fill.py exits 1 when a fixture field or appearance state does not match.

## Flows that are not routes

### verify-and-preview

Status: partial.

DashboardLayout builds an I-130 payload from Convex basics, addresses, and employment, prefers the sessionStorage basics draft, and shows the PDF in an iframe. A signed-in preview goes through a Convex action that decrypts SSN and A-Number server-side. Demo mode uses the fake couple and the Next proxy, which strips those identifiers. Employment is passed in and then ignored. The header no longer shows a hardcoded percent.

Reach it from the Preview my forms button in the app header, on any /sections or /forms page.

Verify: apps/web/e2e/review-package.spec.ts drives the button with a mocked /fill/i-130 response. It needs Convex and Playwright, so it is not part of bun run check. Fill accuracy without the browser is eval_fill.py.

### export-fixture

Status: wired.

Development-only header button. It builds the fixture from saved Convex records, not the unsaved sessionStorage draft, downloads {payload, expected_values}, and copies expected_values from text fields only.

Reach it from the Export Fixture button in the header when NODE_ENV is development.

Verify: No unit test covers the button. The downloaded shape is what eval_fill.py accepts. Confirm against apps/api/scripts/eval_fill.py _load_fixture.
